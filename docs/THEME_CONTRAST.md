# 动态主题对比度

旧主题直接使用固定 HSL 明度。相同的 HSL 明度在不同色相下有不同的相对亮度；浅色主题遇到饱和黄、绿、青色时，白色按钮文字和背景过于接近。饱和黄色的按钮配色原为 `#a0a022` / `#ffffff`，对比度约 2.78:1。

现在主题生成独立于 DOM，按 sRGB 相对亮度计算对比度，调整界面颜色的明度。文字配色计算目标为 4.6:1，给颜色量化留出余量；输入边框的计算目标为 3.1:1。对比度计算依据 [WCAG 2.2 定义](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio)，普通文字的 4.5:1 要求见 [W3C 解释](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

| 浅色主题主色种子 | 按钮背景 | 白字对比度 | 在最高容器层级上的主色文字对比度 |
| --- | --- | ---: | ---: |
| 黄色 `#ffff00` | `#6b6b17` | 5.61:1 | 4.60:1 |
| 绿色 `#00ff00` | `#197619` | 5.76:1 | 4.66:1 |
| 青色 `#00ffff` | `#187272` | 5.69:1 | 4.63:1 |
| 蓝色 `#0000ff` | `#2222a0` | 11.64:1 | 9.03:1 |

表格为展示而四舍五入；测试比较未取整的数值。深浅主题切换时，文字与背景颜色立即应用，保留位置、透明度及阴影的动画，避免颜色同时反转时短暂出现灰字 / 灰背景。输出尺寸的小字提高到 90% 不透明度，数值输入采用可辨识的边框。

验证范围：

- 纯逻辑测试涵盖全部整数色相、预设色和黑 / 白 / 灰色种子，检查深浅主题的文字配色与边框。
- Chromium 检查黄、绿、青、蓝种子在深浅主题下实际计算出的按钮、标题、尺寸小字、输入文字及边框颜色；尺寸小字包含透明度与背景合成。
- 桌面及手机生产截图已检查。整体 WCAG 合规需要其他准则和完整人工检查，本记录只证明上述配色范围。
